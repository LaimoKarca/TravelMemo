# TravelMemo 系統規格

## 產品與環境

多人私人旅遊回憶 Web App。Python 3.12/FastAPI、Vue 3/TypeScript/Vite、Neo4j Community
（圖與內建 Vector Index）。支援本機虛擬環境開發（.venv），以及使用獨立 Docker Compose
專案與 Cloudflare Tunnel 部署。設定從 .env 載入，秘密與個人資料不提交。

以允許名單內信箱與 SMTP 六位數驗證碼登入，無密碼、無公開註冊與管理員頁面。
名單放 .env；工作階段七天，正式環境 Secure/HttpOnly/SameSite 與 CSRF 防護。
驗證碼十分鐘、重寄六十秒、最多五次猜測，具信箱與 IP 頻率限制。
所有 CRUD、搜尋、對話與引用由後端依目前使用者限制；跨帳號資源返回不存在。

## 核心資料與介面

User OWNS Trip HAS_EVENT Event；Event AT Place、HAS_CATEGORY Category，
同一使用者同一旅程的相鄰 Event 以有向 NEXT 相連。
同地重訪保留不同 Event ID，Place 以獨立 ID 選取，不按同名自動合併。
Trip 含名稱、日期範圍、時區與描述。Event 含日期、選填時間、地點、城市、類別、地址、心得。
開始日期不得晚於結束日期，支援同日旅程；新增表單預設結束日期為隔日，並修正隨開始日期改變而過早的結束日。
手記列表提供關鍵字、年份與旅程狀態篩選，開始日期由近到遠排列。
時區預設 Asia/Taipei，可搜尋世界國家與城市的 IANA 時區，或自訂 UTC-12:00 至 UTC+14:00 固定偏移。
依日期排列，同日以使用者確認順序為準；不造時間。NEXT 可跨日並保留日期脈絡，
只表示下一筆已記錄活動。插入刪除重排在交易內重接 NEXT，防循環與跨使用者/旅程連結。
八小時 trail 清洗僅屬 benchmark。編輯採版本檢查，衝突返回 409。

API `/api/v1`：auth/request-code、verify-code、logout、me；trips 與 events CRUD、
trips/{id}/event-order 與 footprint-drafts；search；conversations、messages 與 requests；writing/polish；usage/me；health/live、ready。
前後端使用同網域。搜尋回傳事件、名次、理由及關係證據；對話回傳回答、引用與
answered/insufficient_evidence/needs_clarification/unavailable 狀態。

## 檢索與生成

BM25 與 multilingual-e5-small 向量模型，
384 維正規化向量，query:/passage: 前綴。Neo4j 向量搜尋內先篩 owner，不能全站 Top-K 後過濾。
各取前 50，以 k=60 等權 RRF 融合，同分以 Event ID 排序。
事件編碼只用自身欄位；完整心得保留，截斷有紀錄。
實際文字規則解析前置地點、方向及類別，錨點前五筆沿 NEXT 一跳，按期中提案以
標準化混合 H 與關係 R 各 0.5 重排；無解析/無關係候選時用 H。
「之後」無法確認是否相鄰時澄清。索引工作狀態持久化，重啟恢復，修改排除舊向量，寫回核對版本。

OpenAI 官方 Python SDK Responses API，預設 gpt-6-luna（依使用者後續指定），僅 GPT-5 或更新世代，
不降級到舊模型。全域 Key 放 .env。store=false，本地存對話，必要歷史及證據才外送。
結構化輸出驗證引用屬本人且來自本次證據後顯示。含糊追問先澄清，無證據不編造。
歷史引用修改/刪除可辨識，追問重取資料；紀錄不是指令。API 失敗不影響紀錄管理與搜尋。
不設每日次數上限、不在介面顯示用量；保留每人同時一筆、全站兩筆的並行保護。
直接輸入首則問題建立對話，由模型產生標題；歷史對話可收合。
以持久請求識別碼排隊處理並輪詢結果，關閉頁面或斷線後可回到原對話接續；程序重啟恢復未完成工作，
重送相同請求不重複建立訊息。這不保證外部模型只計費一次。
模型可從固定唯讀工具查找本人旅程、事件及圖片。尚未新增足跡的手記可被查詢，旅程層級回答使用獨立來源引用。
一般招呼自然回覆，個別到訪事實仍要求 Event 證據。
安全流程採正規化、明確攻擊規則及結構化模型分類；失敗不放行，通過後才寫入訊息與查詢資料。
上下文採近期原文、較舊內容分批滾動摘要與完整 JSON 提示大小上限；摘要只作話題記憶，不作旅程證據。
實作與設定見 [後端處理流程](BACKEND.md)。

## 描述建立足跡

手記詳情提供「幫我記足跡」獨立面板，帶入目前旅程。使用者先選旅程內的記錄日期，再輸入最多一萬字元的描述，
模型以結構化輸出整理最多二十筆待確認足跡；不在原有回憶對話中寫入事件。第一版只接受文字，不讀取圖片作為新增依據。

使用者可修改、勾選及調整同日草稿順序，補齊地點與日期後確認批次加入。未指定日期使用記錄日期，
「今天／昨天」以該日期為基準；未知時間留空，分類不明使用「其他」，不造店名、地址或經歷。
明確重訪保留獨立候選，草稿不進入時間軸、檢索或來源證據。

FootprintDraft 以擁有者、旅程、版本及生成請求管理，關閉或斷線後可接續，程序重啟可恢復生成工作。
重新整理先確認取代現有草稿；失敗保留描述與草稿。確認時驗證草稿及 Trip 版本，衝突回傳 409。
全部 Event、Place、Category、NEXT 與去重結果在同一交易寫入，Trip 版本更新一次，失敗不留下部分紀錄。
新事件按日期接在同日既有紀錄後，維持預覽順序；不修改既有事件，重送確認不重複新增。

## 運作與資料範圍

Docker Compose 與 Tunnel 提供自行部署入口，資料保存在獨立持久卷；更新前備份並保留回退方式。
檢索評估與私人旅程資料分離，使用一致的模型與輸入設定，分別比較精確向量及近似向量搜尋。

圖片以壓縮檔保存於私人資料卷，Neo4j 保存附件、解析與搜尋資料；支援旅程相簿、事件附圖、
圖片理解後的文字檢索及聊天附圖。個人經歷仍需事件來源，不能由圖片推定到訪日期或順序。
旅程相簿預設收合，可上傳自訂封面；不設二十張的相簿數量上限，保留檔案及儲存空間限制。
搜尋列與聊天輸入區以圖片圖示開啟拍照／圖庫選單；足跡頁保留兩個直接入口。
旅行描述與足跡心得可按需 AI 潤飾，先預覽、套用或復原原文，再由使用者儲存；不得補造經歷。
前端提供手機主畫面圖示與 manifest，沒有離線私人資料快取；資料讀寫與 AI 使用仍需網路。
地圖、分享共編、個人 Key、公開註冊及完整研究管理介面延後。
