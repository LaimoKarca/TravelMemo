# 示範資料與功能試問

[文件索引](README.md)

這份指南把原創繁中假資料、匯入操作與功能題庫放在同一處。你可以先匯入，再從下方選題到介面試問，依來源核對結果。
資料包含 **12 本手記、150 筆足跡、6 張示意圖卡與 50 個測試案例**；名稱以「【示範】」開頭，與自己的旅行紀錄容易區分。

內容參考 [fuzzy-travel-recall-benchmark](https://github.com/LaimoKarca/fuzzy-travel-recall-benchmark) 的語意、時間地點及前後站查詢概念，手記、心得、日期安排與圖卡另行創作。
它不是原始資料的翻譯，不含原始使用者軌跡，也不是研究評估成績。正式檢索比較見[檢索評估](EVALUATION.md)。
公開資料來源是 [scenarios.json](../examples/demo/scenarios.json)；其中的鍵值只用來對照題目，不是網站產生的資源 ID。

## 匯入到自己的測試帳號

先依[本機啟動](GETTING_STARTED.md)或[部署說明](DEPLOYMENT.md)完成環境與資料庫初始化。
將目標信箱放進私人 `.env` 的允許名單，重啟 API；使用自己的信箱替換下列通用範例。

先預覽，不寫入資料：

```powershell
.\.venv\Scripts\python.exe main.py seed-demo --email tester@example.com
```

確認目標與數量後才套用：

```powershell
.\.venv\Scripts\python.exe main.py seed-demo --email tester@example.com --apply
```

使用專案 Docker Compose 部署時，可在 API 容器執行相同命令；省略 `--apply` 即為預覽：

```powershell
docker exec travelmemo-api-1 python main.py seed-demo --email tester@example.com --apply
```

正式 Compose 環境在 API 容器內執行相同入口，例如：

```powershell
docker exec travelmemo-api-1 python main.py seed-demo --email tester@example.com
docker exec travelmemo-api-1 python main.py seed-demo --email tester@example.com --apply
```

匯入只作用於明確指定、允許名單內的帳號。尚未登入過的信箱可預先建立資料節點，但不建立登入工作階段；使用介面時仍須正常收驗證碼登入。
既有手記不會被清空或覆寫。旅程、事件與 NEXT 先以交易建立，再補入圖卡與相簿連結；重跑跳過已完成部分，圖片階段失敗時可用相同命令續補。
已手動修改或刪除的示範紀錄不靠重跑還原；需要改動資料的測試，請使用後述獨立練習手記。

### 日期與索引

首次匯入以台北當地日期作基準，也可加 `--anchor-date YYYY-MM-DD` 指定。手記日期由相對天數換算後保存，後續重跑不會讓日期漂移。
下表與題目以「第 N 天」描述；實際日期請查看手記日期範圍。手記中有 9 本過往、1 本旅行中、1 本未來及 1 本空手記，狀態會隨時間改變。
同一天的足跡順序以資料內順序為準，未知時間仍為空值；顯示倒序不改變「紀錄中的下一站」。

事件向量與圖卡解析沿用既有背景流程。請先等索引與圖片準備完成，再判斷語意或圖片題是否命中；失敗排查見[搜尋與對話](RECALL.md)及[圖片說明](PHOTOS.md)。
圖卡是原創示意圖片，不是真實旅行照片。圖片理解與手動試問會使用已設定的 AI 服務；匯入不會自動批次發送整份題庫。

## 如何核對

- 搜尋與 AI 題目可直接複製問題，必要時先在介面指定手記。AI 不必逐字回答成下表的句子，但事實、日期脈絡與引用來源須一致。
- 同一地點多次到訪是不同足跡；沒有足夠條件時應澄清，不能只靠店名猜中某一次。
- 「下一站」是下一筆已記錄足跡，跨日時須保留日期脈絡；「之後」若意思不明應先澄清。
- 操作題在表內列出步驟；標成「會修改資料」的題目，先建立獨立練習手記，手動複製所需文字與圖片再做。不要直接刪改其他題目的原始依據，完成後可刪除練習手記。
- 圖卡只能證明可見內容，不可憑圖片推定未記錄的到訪。空手記的名稱、日期與描述可被列出，但不能當成到訪證據。
- 這裡列的是可重用的測試情境與預期，不包含任何實際測試結果。完成試問後可另存私人筆記。
