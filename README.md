# TravelMemo

**把旅途中的每次到訪，整理成能回顧、能找回的個人回憶。**

TravelMemo 是可自行部署的旅遊回憶管理 Web App。你可以依旅程保存地點、日期與心得，
透過時間軸重看走過的行程，並保留每次到訪之間的順序關係。

即使只記得「那天去完某個景點後的下一站」，也能結合文字、語意與圖關係尋找紀錄，
再透過附來源引用的 AI 對話回顧旅程。

TravelMemo is a self-hosted travel memory app with private journals, event timelines,
hybrid search, and evidence-backed AI conversations.

## 功能介紹

| 功能 | 說明 |
| --- | --- |
| 私人旅程手記 | 建立與編輯旅程名稱、日期範圍、時區與描述 |
| 到訪紀錄 | 保存日期、選填時間、地點、城市、類別、地址與心得 |
| 旅程時間軸 | 依日期瀏覽行程，調整同日事件順序，依城市及類別篩選 |
| 重複到訪與地點重用 | 同一地點可被多次造訪，每次都保留獨立紀錄 |
| 行程順序關係 | 用 Neo4j 的 NEXT 關係保存「紀錄中的下一站」 |
| 信箱驗證碼登入 | 以允許名單與郵件驗證碼控制登入，各帳號資料私有 |
| 編輯衝突提示 | 不同分頁同時修改時提示衝突，避免覆蓋新資料 |
| 混合回憶搜尋 | 以 BM25 與多語 E5 向量檢索找回不完整線索中的事件，支援旅程、日期、城市及類別篩選 |
| 上一站／下一站查詢 | 依有向圖關係尋找相鄰紀錄，保留跨日日期脈絡；有歧義時先澄清 |
| AI 多輪對話 | 參照對話中的事件來源追問，回答附可點擊引用，並顯示已變更或已刪除的來源 |
| 自然開啟對話 | 直接輸入問題，自動建立對話與摘要標題，歷史紀錄可收合 |
| 有限上下文記憶 | 近期原文搭配較舊對話的滾動摘要，控制每次送給模型的內容大小 |
| AI 安全分流 | 規則與模型分類攔截明顯攻擊，回答前驗證來源與資料權限 |
| 圖片手記 | 旅程相簿、封面與到訪事件附圖，支援手機拍照及圖庫上傳 |
| 看圖回憶 | 自動整理圖片摘要與可見文字，用圖片搜尋旅程、在對話中附圖及查看來源 |
| 自架與資料維護 | Docker 部署、Cloudflare HTTPS 入口、索引重建、備份與隔離還原演練 |

時間不詳可以留空；系統不會補造精確時間。NEXT 表示下一筆已記錄的到訪，
不代表途中沒有其他未記錄的活動。

## 如何使用

1. 使用允許名單內的信箱取得驗證碼並登入。
2. 建立一趟旅程，填入日期範圍與描述。
3. 逐筆加入到訪地點與心得，必要時重用既有地點。
4. 從時間軸回顧旅程，補充內容或調整同日紀錄順序。
5. 到「回憶搜尋」輸入記得的線索，或開啟「AI 對話」追問，點來源回到原紀錄。

若要公開提供服務，可依下方文件自行部署獨立站台，並透過信箱允許名單控制登入權限。

## 技術架構

- **後端：** Python 3.12、FastAPI。
- **前端：** Vue 3、TypeScript、Vite。
- **資料庫：** Neo4j Community，保存圖資料、對話與向量，使用內建 Vector Index。
- **檢索：** multilingual-e5-small、BM25、RRF 融合與查詢導向 NEXT 遍歷。
- **AI：** OpenAI Responses API、結構化輸出、伺服器引用驗證。
- **部署：** Docker Compose、Nginx、Cloudflare Tunnel。

E5 在自己的主機編碼；啟用 AI 對話時，必要的對話歷史與檢索證據會送至 OpenAI。
未設定 OpenAI Key 時仍可管理旅程與搜尋。

## 研究基礎

本專案延伸自 [fuzzy-travel-recall-benchmark](https://github.com/LaimoKarca/fuzzy-travel-recall-benchmark)，
研究如何從不完整線索找回個人到訪事件，並比較 BM25、E5 向量檢索與圖結構輔助排序。

benchmark 專案提供實驗與可重現比較；TravelMemo 將此研究方向延伸成可使用的旅遊回憶管理系統。
本系統以固定公開資料、文字表示、模型設定與參數另行評估；既有 benchmark 分數不直接視為本系統的成績。
檢索評估方法論與重現步驟見[檢索評估說明](docs/EVALUATION.md)。
